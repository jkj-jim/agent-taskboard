# 更新记录规则

`document/updates/<YYYY-MM>.md` 汇总已完成的新产品逻辑和项目运行机制。它是回顾用的存档，不是任务依据，也不进入默认读取链——只有在写入或查询时才读本文件取规则。

## 写什么

- 只记最终结果：某个功能现在是什么行为、某条机制现在怎么运转。
- 不记过程：不写「改了哪些文件」「先怎样后怎样」「修了什么 bug 的经过」，这些留在任务评论里。
- 同一天内同一功能反复迭代，覆写原条目，不追加新条目。
- 每天一个 `## <YYYY-MM-DD>` 小节，条目用 `-` 列表。

## 怎么写入

先只取当天小节，确认是否已存在：

```bash
awk -v d="$(date +%F)" '$0 == "## " d {p=1} p && /^## / && $0 != "## " d {exit} p' "document/updates/$(date +%Y-%m).md"
```

- 当天小节已存在：在该小节内改写或追加条目。
- 当天小节不存在：只用 `tail -n 20` 看文件尾部，再在末尾追加新小节。
- 月文件不存在：直接新建，首行写 `# <YYYY-MM> 更新`。

## 怎么查询

仅在用户明确查历史时才查。先定位再有界读取，不要通读月文件：

```bash
rg -n -m 5 "关键词" document/updates/
```

命中后用 `sed -n '<起>,<止>p'` 或上面的 awk 取对应日期小节。

## 硬性约束

- 任何情况下都不要一次性读取整篇月文件。
- 不要为了写更新记录去回溯 git log 或通读代码，写入内容以当前对话已确认的结论为准。
