# 2026-08 更新

## 2026-08-06

- 项目运行机制：非琐碎变更由本项目 Taskboard 驱动，议题与评论承载任务上下文，`manage-taskboard` skill 按需加载；Agent 定点读取代码完成最小闭环，月度更新只保存最终摘要。

## 2026-08-07

- 双 Agent：议题负责人可选 Codex Agent 或 Claude Agent，选中者承接后续开发。共用定义集中在 `shared/agents.mjs`，差异只允许出现在 `server/agents/*` 与 `web/src/agents.ts`。
- Claude 接入走官方通道：`claude` CLI 无头执行 + `claude://` 深链 + `~/.claude` 状态文件。桌面端侧边栏嵌入不可行——主进程启动即校验 CDP 签名，该方向不再尝试。
- 会话归属：每个议题对每个 Agent 各留一条当前会话，`taskctl` 调用时按请求身份从 `CODEX_THREAD_ID` / `CLAUDE_CODE_SESSION_ID` 自动绑定，议题详情按 Agent 渲染「在 X 中打开」。不提供手工挑选已有会话的入口，与 Codex 保持一致。
- 桌面端打开 CLI 会话是导入副本而非接管：同一会话只导入一次，但会话正开在终端里时两侧会各自续写。
- Claude Code 没有 OS 级沙箱，`workspace-write` 与 `danger-full-access` 同为 `bypassPermissions`，界面标注该档位等同全放行；需要逐条审批只能用 `read-only`。
- Claude Agent 使用 Claude Code 图标，负责人行与评论头像可与 Codex 区分。
- 测试基线清零：`npm test` 全绿（376 用例），任何失败都可直接判定为回归，不需再比对历史基线。
- 协作规则：对话中提出的需求不强制归入 Taskboard，识别到值得长期跟踪时先征求用户同意；更新记录的写法与有界读取命令收在 `document/updates/RULES.md`，按需读取。
