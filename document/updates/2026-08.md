# 2026-08 更新

## 2026-08-06

- 项目运行机制：非琐碎变更由本项目 Taskboard 驱动，任务与评论承载任务上下文，`manage-taskboard` skill 按需加载；Agent 定点读取代码完成最小闭环，月度更新只保存最终摘要。

## 2026-08-07

- 双 Agent：任务负责人可选 Codex Agent 或 Claude Agent，选中者承接后续开发。共用定义集中在 `shared/agents.mjs`，差异只允许出现在 `server/agents/*` 与 `web/src/agents.ts`。
- Claude 接入走官方通道：`claude` CLI 无头执行 + `claude://` 深链 + `~/.claude` 状态文件。桌面端侧边栏嵌入不可行——主进程启动即校验 CDP 签名，该方向不再尝试。
- 会话归属：每个任务对每个 Agent 各留一条当前会话，`taskctl` 调用时按请求身份从 `CODEX_THREAD_ID` / `CLAUDE_CODE_SESSION_ID` 自动绑定，任务详情按 Agent 渲染「在 X 中打开」。不提供手工挑选已有会话的入口，与 Codex 保持一致。
- 桌面端打开 CLI 会话是导入副本而非接管：同一会话只导入一次，但会话正开在终端里时两侧会各自续写。
- Claude Code 没有 OS 级沙箱，`workspace-write` 与 `danger-full-access` 同为 `bypassPermissions`，界面标注该档位等同全放行；需要逐条审批只能用 `read-only`。
- Claude Agent 使用 Claude Code 图标，负责人行与评论头像可与 Codex 区分。
- 测试基线清零：`npm test` 全绿（376 用例），任何失败都可直接判定为回归，不需再比对历史基线。
- 协作规则：对话中提出的需求不强制归入 Taskboard，识别到值得长期跟踪时先征求用户同意；更新记录的写法与有界读取命令收在 `document/updates/RULES.md`，按需读取。

## 2026-08-08

- 双 Agent 兼容：`AGENTS.md` 由 Codex 与 Claude Code 共用；修改 Agent 相关能力时先核对共享注册表与两端适配器，共享逻辑不硬编码 Agent 名称，单端能力明确边界并确认另一端主路径不受影响。
- Agent 自动启动：本机 loopback 看板通过运行中的兼容 Codex 客户端后台创建、提交并回写原生任务，不再为 Codex 启动或导入 `codex exec` 会话；后台启动保留浏览器焦点和此前 Codex 页面，只有用户主动打开时才跳转。客户端、注入器或本机能力不可用以及远程访问时只保留任务状态并提示，Claude Agent 继续使用原有 CLI 适配器。
- 任务详情页在属性栏提供删除入口；确认后任务从看板移除并自动返回看板，取消或删除失败时保留当前详情。
- 产品界面、提示、工作流与使用文档统一使用“任务”表述；底层 `issue` API、类型和数据字段保持兼容，原有功能逻辑不变。

## 2026-08-09

- Agent 任务交互：`taskctl issue list` 默认成为活动任务精简索引，排除 `done` / `canceled`，描述折叠空白后最多返回 50 个 Unicode 字符；历史查询显式指定状态，统计、导出和诊断使用 `--all-statuses --full`，CLI 契约升为 `schemaVersion: 3`。选中任务后由 `issue brief` 一次读取完整任务、全部评论与附件。原生 Codex 全程使用绑定实际监听地址的绝对路径 shim，随机或非默认端口下也能完成读取、评论和状态回写；AI 面板与原生启动共用唯一一次 shim 初始化，Claude 原有启动路径保持兼容。完整逻辑沉淀在 `document/agent-task-interaction-mechanism.md`，README 提供稳定入口。
- 评论与定时认领：评论改为按反馈轮次和交付轮次写精炼交接，以 `用户反馈：`、`交付：`、`需决策：`、`阻塞：` 标明意图，300 字是目标而非硬上限；保留影响下一轮的根因、取舍和约束，省略日志与探索过程。定时认领使用同一套 `issue brief` 和交付评论规则，已有自动化会在下次同步时更新提示。
